# Agent 评测数据

运行、指标定义、模拟 usage 的边界与回归流程见 [`docs/agent-evaluation.md`](../../../../docs/agent-evaluation.md)。

- `scenarios.json`：47 条独立合成样本及手工期望；只包含虚构订单，不包含账号密码或真实用户数据。
- `baseline.json`：版本、场景文件 SHA-256、必备 ID 和门槛。文件摘要按 UTF-8、LF 换行计算。
- `RULES` 使用真实离线规划器；其他 `planner` 值是明确命名的故障注入，不是语言模型对这句话产生了该结果。
- 每个场景创建独立临时店铺，认证身份与店铺条件分开；公开数字 100/101 为逻辑店铺标签。
- 不能删掉失败场景或根据当前输出自动重写期望；变更标签应同时解释业务规则、版本和基线。

JSON 期望中的 `capabilities` 是已尝试能力的去重集合；重复鉴权读取保留在报告 `callTrace`。`phases` 是持久化 Agent 的完整已启动步骤顺序。`ticketDelta` 只允许 0/1；获准提交的请求仍必须保持等待人工审核，不能产生退款执行任务。

报告输出到 `target/agent-evaluation/`。数据集校验失败、缺少样本或计数分母为零，不能算作一次成功验收。
