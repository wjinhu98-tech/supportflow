# 售后申请与人工审批流程

本项目学习版售后记录申请、人工审核、模拟退款处理与审计；不连接支付渠道、不执行真实退款，也不承诺退款到账或期限。外部企业的退款金额、退货条件和服务时效不在本知识库内，不能推测。

提交售后申请前，Java 服务校验认证买家、当前店铺、订单归属和输入；CREATED 或 CANCELLED 状态的订单不能申请售后。客户端或模型不能绕过这些校验。

申请受理后进入 PENDING_REVIEW，等待人工审批。审批需要 AFTER_SALE_REVIEW 权限；学习版拥有该权限的管理员可以审核，但禁止申请人本人审批。人工给出 APPROVED 或 REJECTED，不由模型自行决定审批结果。

重复提交同一个 request_key 对应的相同申请，应返回同一张售后单，不重复创建。已经 APPROVED 或 REJECTED 的售后单不能再次审批，审批结果及其操作者需要保留审计记录。

人工批准与持久化处理任务在同一事务内保存。处理进度为 PENDING（等待执行）、PROCESSING（处理中）、SUCCEEDED（模拟处理成功）、FAILED（处理失败）。后台会继续领取任务，服务重启后可接续未完成的任务。临时失败按退避计划自动重试，管理员也可提前重试；自动与手工重试共用最多5次尝试预算。

模拟金额来自已批准订单，执行前 Java 再校验审批、订单归属、状态、金额与币种。相同售后单只保留一份模拟退款回执。处理状态、回执和成功审计在同一事务内提交；买家可以在「售后进度」或发送「我的售后」查询。订单信息不满足条件时停止处理，请管理员核查。

本流程写售后单、处理任务、模拟退款回执和审计记录，不修改 support_order 的状态或金额。APPROVED 是审批结果，SUCCEEDED 是模拟处理结果，均不代表真实支付渠道退款或资金已到账。旧版本已经审批但没有处理任务的记录不会自动补执行。
