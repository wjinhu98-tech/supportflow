# 每店一个聊天窗口

V15 起，买家在每家店铺有一个固定聊天窗口，连接账号、刷新或切回同一家店铺都继续使用它。“新会话”改为“删除对话”，历史咨询工具栏继续隐藏。店铺切换弹窗列出店铺名称，也保留输入 ID 的入口。

旧会话和消息不自动清空或移动。固定窗口读取该买家在该店铺所有未删除咨询，按原消息顺序显示，最新一页最多 40 条，向上加载使用 UUID 游标。旧物理会话编号和 Agent Checkpoint 保留；新消息写当前固定窗口。数据库唯一键保证多个浏览器同时打开仍返回同一窗口。

旧快照不会自动重开退款表单、执行工具或选择历史订单。当前话题由服务端单独返回，不从另一旧会话的最后一条卡片直接继承。

## 主动删除

确认框说明删除**当前账号、当前店铺的全部聊天，包括以前的咨询**。取消不发请求。页面在聊天、确认收货或退款提交期间禁用删除，后端也拒绝仍有有效处理轮次的窗口。

会话采用逻辑删除，聊天端不能再通过历史、发送或 Agent 恢复接口访问；底层消息和运行审计保留，不是物理擦除。订单、售后申请、审批、退款任务与其他店铺聊天不受影响。

DELETE 携带已确认的窗口 UUID，验证买家、店铺与 CSRF。继续咨询产生新 UUID；旧删除请求重复到达不会删除新窗口。网络结果不明时不自动重发 DELETE，保留画面并通过 GET 核实。迁移和部署不会自动删除任何既有聊天。

## 接口与实现

| 接口                                                            | 用途                                                           |
| --------------------------------------------------------------- | -------------------------------------------------------------- |
| GET `/api/v1/shops`                                             | 有订单读取权限的买家读取最多 50 个店铺标签，不返回商家员工身份 |
| POST `/api/v1/shops/{shopId}/chat/window`                       | 幂等打开窗口，需要 CSRF                                        |
| GET `/api/v1/shops/{shopId}/chat/window?beforeId={messageUuid}` | 只读恢复和分页，不创建或重新打开窗口                           |
| DELETE `/api/v1/shops/{shopId}/chat/window/{conversationId}`    | 删除已确认的店铺窗口，需要 CSRF                                |

消息仍通过原 `/chat/conversations/{conversationId}/messages` 提交，沿用轮次幂等、身份校验、Agent 预算和双代次恢复保护。旧会话 API 保留用于兼容已有集成。

`ShopConversationController` 提供入口，`JdbcConversationStore` 负责唯一窗口与删除，`JdbcAgentRunStore` 排除已删除会话的运行；`useSupportDesk` 组织打开、切换、恢复与删除结果核实，`App.vue` 展示店铺选项和确认弹窗。

[V15 迁移](../src/main/resources/db/migration/V15__shop_chat_windows.sql)只给原会话表增加字段、索引和约束，沿用已有表级权限，无须授予数据库 DELETE 权限。

## 两个新演示店铺

| 店铺 | 名称       | 演示订单                             |
| ---- | ---------- | ------------------------------------ |
| 102  | 数码优选店 | `SF102001` 已发货，`SF102002` 待发货 |
| 103  | 生活家居店 | `SF103001` 已发货，`SF103002` 待发货 |

四笔订单属于演示买家 200；两笔已发货订单有明确标注的学习物流事件，没有伪造确认收货。既有店铺和订单不修改。按用户选择，`support-reviewer` 仍只管理店铺 100。

`DemoShopData` 是显式事务化导入工具，不是 Spring Bean，不随 Flyway 自动运行；重复执行不覆盖原订单，店铺编号冲突则回滚，不授予员工权限。临时浏览器测试启动器使用相同的假数据。Docker 实验环境可显式执行：

```powershell
docker compose -p supportflow-lab -f deploy/compose.yml run --rm --no-deps migrate seed-shops
node scripts/check-shop-windows-lab.mjs
```

前者只导入两个店铺和四笔订单；后者只对固定实验地址发 GET，检查名称、订单归属、窗口读取和原商家授权，不修改聊天、不调用模型。

2026-10-27 验证：后端 476 个单元测试和 315 个集成测试、前端 426 个测试与生产构建通过。24 个模拟浏览器用例和 4 个真实 Java / MySQL 用例覆盖切店恢复、旧记录分页、取消删除、确认删除、重复删除和话题恢复。所有删除验证只在临时测试库执行。
