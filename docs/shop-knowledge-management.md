# 商家店铺知识库管理

## 这轮解决什么问题

原知识库只有随应用发布的公共 Markdown。现在商家可在 `/merchant` 维护获授权店铺的 FAQ，买家咨询时只检索当前店铺已发布的资料与明确公开的应用说明，不读取其他店铺草稿或未发布内容。

本轮只支持有长度限制的纯文本标题、关键词和正文，不提供文件上传、外部网址抓取、富文本执行、向量数据库或后台自动生成政策。

## 草稿和对客版本分开

- 新建知识先保存为草稿，不参与买家检索。
- 发布时保存不可变的内容快照。修改已发布文章只更新草稿，之前的发布版本继续对客生效；再次发布才替换快照。
- 下线会让新咨询停止引用该文章，不删除历史快照、审计或已保存的聊天记录。历史回复是当时引用的记录，不代表内容仍在生效。
- 保存、发布和下线都提交读取时的 `expectedVersion`。版本过期返回409，前端保留输入并要求读取最新状态，不覆盖他人的修改，也不自动重放写请求。

每店最多100篇同时发布的文章，发布名额由数据库唯一约束保证，并发发布竞争不会静默超过上限。管理列表和审计采用有界分页，检索不把全平台文章先取到内存再过滤。

## 权限与业务边界

新增独立的 `KNOWLEDGE_MANAGE` 权限。员工还须有有效商家绑定与当前店铺授权；仅有知识维护权限不代表可审批退款、查看买家订单或调用买家接口。售后审核仍要求原有审核权限。

写入在事务中锁定当前店铺授权，知识变更与员工审计原子提交。撤权不依赖重启：撤权先提交则后续操作拒绝，已经合法取得授权锁的写事务先完成后撤权再提交。

知识文章是引用资料，不是模型或工具的指令。文章中的“忽略规则”“直接退款”等文字不能触发业务操作。售后期限、订单归属、确认收货和人工审批仍由已有业务校验决定；不能通过编辑 FAQ 改变确认收货后15天的售后规则。

新回复保留来源标识、发布版本与引用原文。公开响应的 `knowledge.status` 区分 `ANSWERED`、`NO_MATCH` 与 `UNAVAILABLE`；短答与 `knowledge.sources` 中的完整来源快照分开，前端默认折叠展示。无足够依据时不编造答案；明确查单、申请退款和查询处理进度的路径不因 FAQ 命中而被改写。有限同义表达与评测边界见[知识问答质量说明](knowledge-quality-and-interview.md)。

## 本地配置

继续使用原商家入口、账号和密码，只为需要维护知识的员工增加 `KNOWLEDGE_MANAGE`。店铺范围仍来自原授权表，不因新增功能扩大到其他店铺。

数据库升级采用V10创建知识表、V11补强发布状态的非空约束，不修改已执行迁移，也不自动发布演示政策。运行账号仅获得知识当前表所需的读写、发布快照的读取与插入、审计的读取与插入权限，不授予DELETE、DDL或商家授权表写权限。

需要由有授权权限的数据库管理员在V10迁移后执行 [`config/knowledge-runtime-grants.sql`](../config/knowledge-runtime-grants.sql) 的全部内容（三条GRANT及最后的SHOW GRANTS）。不要将root凭据放入应用配置；本地密码和密钥仍保存在被Git忽略的文件中。

## 接口与输入范围

所有知识管理接口均位于 `/api/v1/merchant/shops/{shopId}/knowledge`：

| 方法与子路径 | 用途 |
| --- | --- |
| GET 根路径 | 当前店铺文章，每页20条；`beforeId`继续读取 |
| POST 根路径 | 创建草稿，仅提交 `title`、`keywords`、`content` |
| GET `/{id}` | 文章草稿和当前发布快照 |
| PUT `/{id}` | 保存草稿，另提交 `expectedVersion` |
| POST `/{id}/publish` | 发布当前草稿，仅提交 `expectedVersion` |
| POST `/{id}/offline` | 下线，仅提交 `expectedVersion` |
| GET `/{id}/audit` | 当前文章审计，每页20条；`beforeId`继续读取 |

标题最长120字符；关键词1至12项，每项最长40字符；正文最长4000字符。服务端决定文章UUID、店铺、员工身份、发布时间、发布修订号和审计，客户端不能提交或伪造这些字段。

文章的 `version` 是从0开始的并发控制版本，`publishedRevision` 是发布修订号，两者用途不同。`publishedSnapshot` 代表当前对客生效的不可变内容，不是尚未发布的编辑内容。列表与审计都返回 `{items,nextBeforeId}`；没有下一页时游标为null。

## 手动查看一条完整流程

1. 商家登录 `/merchant`，选择“知识库管理”，新建“礼盒包装说明”，填写相关关键词与自己确认过的正文，保存草稿。
2. 买家在当前店铺发送“知识库：礼盒包装”，草稿内容不应出现。
3. 商家发布后，买家再次发送同一问题，回答应包含原文和 `kb-UUID@vN` 来源。
4. 商家修改并保存草稿，买家仍读取之前的发布内容；重新发布后，新咨询才使用新修订。
5. 下线后，新咨询不再引用该文章；历史咨询保留当时的引用。商家可展开操作记录核对各次内容。

选中订单后的简短追问优先沿用真实订单查询，金额、归属、状态等不能被FAQ抢答。需要显式查资料时可使用“知识库”前缀，受保护的售后/订单事实问题仍不会采用商家自行填写的声明。普通未选单咨询有可靠FAQ命中时可直接回答，不必输入前缀。
