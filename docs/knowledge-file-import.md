# 商家知识文件导入

商家在 `/merchant` 的知识库选择「导入文件」，上传本店的 TXT 或 Markdown。系统先展示纯文本预览；只有点击「确认保存为草稿」才写入，发布仍需现有的显式发布操作。取消预览不会创建文章。

## 输入和处理范围

- 扩展名 `.txt`、`.md`、`.markdown`，严格UTF-8，可带BOM；文件最多64KiB，正文沿用现有4000字符上限。超限明确拒绝，不截断正文。
- 正文只移除开头BOM、统一换行和首尾空白；不执行Markdown、HTML或脚本，不抓取文中链接。
- 标题和1–12个关键词可在预览后填写。确认时重新上传并解析文件，服务器不信任前端提供的正文摘要、hash或预览令牌。
- Servlet接受的文件在内存解析；Nginx总请求上限及内存缓冲均为128KiB。应用不保存原文件、临时文件路径或原文件名；数据库保存草稿正文和规范化内容的去重记录。这不保证操作系统不会交换内存。

## 数据如何流动

```text
本店知识维护账号 → 上传文件 → 店铺授权检查 → UTF-8解析 → 预览（不写库）
  → 确认标题和关键词 → 重新校验店铺授权及文件 → 保存草稿 + 导入记录 + 创建审计
  → 人工发布 → 当前店铺知识检索与来源引用
```

确认事务以店铺和规范化正文SHA256生成稳定文章ID，在原有可写文章行上串行化同内容导入，导入记录表只需SELECT/INSERT。并发重复只创建一篇草稿、一条导入记录和一次创建审计；同一内容在另一店铺得到独立文章。

重复导入会打开原文档，不覆盖随后编辑的正文、标题、关键词、版本或发布快照。导入记录和草稿/审计在同一事务提交；任何一步失败均回滚。文章下线、历史快照和发布名额继续使用原有规则。

## 接口和权限

| 接口                                                             | 输入                                                       | 返回                                     |
| ---------------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------- |
| POST `/api/v1/merchant/shops/{shopId}/knowledge/imports/preview` | multipart：`file`                                          | `title/content/characterCount/byteCount` |
| POST `/api/v1/merchant/shops/{shopId}/knowledge/imports`         | multipart：`file/title/keywords`；keywords为JSON字符串数组 | `articleId/reused`                       |

两者都需要商家账号、`KNOWLEDGE_MANAGE`、当前有效店铺授权及CSRF。预览不授予后续写入资格：确认时重新锁定并核对授权。格式错误返回400，超大文件返回413，错误码为`KNOWLEDGE_IMPORT_INVALID`；网络结果不明不自动重放，应刷新知识列表核实。

导入的商家资料始终视为本地资料，不会因与公开参考相似而变成公开资料，也不发送给DeepSeek。只有已发布正文参与本店检索；草稿、其他店铺资料和下线资料不参加新回答。

## 启用

V19新增不可变的`support_knowledge_import`。日常库迁移后，由管理员执行[`config/knowledge-import-runtime-grants.sql`](../config/knowledge-import-runtime-grants.sql)全部内容，只给新表SELECT、INSERT，不授予更新、删除或授权关系修改。原知识文章、发布快照和审计权限不变。

Docker沿用`migrate → grant → backend/frontend`升级顺序，保留现有数据卷；原文件不进入镜像构建或Git。日常库不自动导入或发布示例资料，测试使用一次性MySQL和独立商家账号。
