# DeepSeek 共享调用保护

本文记录共享 HTTP 保护的基础机制。当前三个入口均复用该执行器；V14 在其上增加熔断，在持久化 Agent 步骤层增加一次受控重试，见[故障治理说明](agent-resilience.md)。HTTP 执行器自身仍不重试，退款和审批写入不因此重放。

## 解决什么问题

查单意图识别和工具参数规划都可能访问 DeepSeek。原先两个适配器各自实现 HTTP、超时、取消和响应大小限制；每个会话虽然限制同时处理一轮，不同会话仍能同时占用模型连接和等待线程。

现在两个入口使用同一个 `DeepSeekCallExecutor`，每个应用实例共享并发预算。容量满时立即返回已有的 `503 / MODEL_UNAVAILABLE`，不排队等待、不自动重试。订单归属、工具白名单、人工审批和会话幂等仍由原业务流程负责。

## 一次调用的数据流

```text
用户消息 → 原路由与业务服务
  → DeepSeekOrderIntentRecognizer / DeepSeekToolPlanner：构造本入口请求 JSON
  → DeepSeekCallExecutor.execute(operation, requestBody, parser)
      尝试取得共享并发许可
      ├─ 已满：记录 BUSY，不发 HTTP，返回安全的不可用错误
      └─ 取得许可
          → 固定 DeepSeek HTTPS 地址，禁止重定向
          → 等待响应头与完整响应体，执行超时和 64 KiB 限制
          → 适配器严格解析响应及工具参数
          → 失败时尽力取消，始终释放许可，记录一次安全日志
  → 原 Java 权限和业务校验 → 公开响应 / 会话成功快照
```

模型响应通过结构校验，不表示订单存在、账号获权或退款成功。HTTP 错误、无效 JSON、伪造参数、超时和中断都不能变成业务授权。

## 配置与共享范围

公开 `application.yml` 增加：

```yaml
supportflow:
  ai:
    deepseek:
      max-concurrent-requests: 4
```

配置允许 1–64，越界或非整数会阻止启动。默认值是学习环境的有界起点，不是实测最优值；调整前应测量模型延迟、供应商配额、等待线程和拒绝量。Key、模型名、连接超时和请求超时的位置不变，真实 Key 继续只放后端私密配置或环境变量。

Spring 在模型启用时创建一个执行器，并注入两个适配器；关闭模型时不创建执行器或模型 HTTP 客户端。旧构造函数保留用于独立测试和兼容；手动分别构造两个适配器不共享预算，必须显式传入同一个执行器。

许可覆盖 HTTP 等待和响应解析。请求超时限制接收响应头及完整正文的等待时间，不是解析 CPU 时间的强制中断器。响应正文在收取时累计限长，不先收完整个大响应再检查。

这是单实例并发保护，不是每秒限流或跨实例全局配额；两个实例有两份预算。取消是客户端的尽力取消，不能声称已经撤销供应商端处理或扣费。固定查单指令和本地知识检索继续使用原路径，不因模型容量已满而改用模型或编造结果。

## 可以观察什么

执行器每次调用记录一条日志，例如：

```text
deepseek_call operation=TOOL_PLAN outcome=SUCCESS durationMs=42 inFlight=1 limit=4 httpStatus=200
```

示例数字只说明格式，不是项目测量结果。`operation` 是 `ORDER_INTENT / TOOL_PLAN` 固定枚举；`outcome` 区分成功、容量已满、超时、中断、供应商限流/错误、无效响应、传输错误和取消。`durationMs` 包含执行器内的解析时间，不代表用户请求全链路延迟；`inFlight` 是记录时占用许可数的并发采样值，`limit` 是配置上限，未获得完整响应时 `httpStatus=0`。

日志不包含 Key、Authorization、用户消息、订单号、买家/店铺 ID、请求体、供应商正文或异常堆栈。对外仍只抛固定异常，不附供应商异常作为 cause。429 只作内部分类，不重试，也不把供应商正文传给用户。

本模块提供调用边界日志，没有新增公开监控接口、Prometheus 导出、分布式追踪或告警。要量化成功率、拒绝率、P95 和费用，仍需指标采集与统计窗口；固定测试不能当作容量结果。

## 类的作用

| 类 | 输入与返回 | 职责 |
| --- | --- | --- |
| `DeepSeekProperties` | 后端配置 → 校验后的值对象 | 开关、Key、模型、超时和并发上限；字符串表示隐藏 Key |
| `DeepSeekConfiguration` | Spring 配置 → 条件 Bean | 管理客户端生命周期，将同一执行器注入两个适配器 |
| `DeepSeekOrderIntentRecognizer` | 当前消息 → `OrderIntent` | 构造意图识别请求，严格解析模型输出 |
| `DeepSeekToolPlanner` | 允许工具、消息、显式选单 → `PlannedToolCall` | 只接受一个受限工具和合法参数，不执行工具 |
| `DeepSeekCallExecutor` | 固定操作、请求 JSON、解析函数 → 校验结果 | 共享并发、HTTP、期限、取消、异常隔离和安全日志 |
| `DeepSeekResponseBodySubscriber` | 字节块 → 有界字节数组 | 超过累计大小限制前停止收取 |
| `DeepSeekCallOperation / DeepSeekCallOutcome` | 固定枚举 | 不以用户输入生成诊断标签 |

## 为什么采用这个边界

保留两份 HTTP 代码改动较少，但取消、超时和安全日志容易逐渐不一致。分别在两个适配器放 `Semaphore` 也无法形成跨入口总预算。共享执行器同时约束现有网络入口，适配器继续承担各自的协议解析。

没有因此增加 Redis、消息队列、微服务或复杂断路器。当前验证的是单实例上限、立即拒绝、失败释放及协议兼容。跨实例配额、账号公平性、连续故障熔断和完整指标体系是独立需求，需要测量与故障评估支持。

## 验证范围

离线测试使用假 HTTP 客户端、可控 future 和并发信号，不调用真实 DeepSeek、不读取本地私密配置。验证共享容量、满额不发 HTTP、成功/异常/超时/中断/取消后的许可释放、跨入口共享、429 不重试、正文边界以及日志和异常脱敏。既有严格 JSON/工具参数、权限、店铺隔离与会话测试继续回归。

```powershell
mvn -o "-Dtest=DeepSeekCallExecutorTest,DeepSeekConfigurationTest,DeepSeekOrderIntentRecognizerTest,DeepSeekToolPlannerTest" test
mvn -o verify
```

第一条运行模型边界和协议单测，不要求真实 Key；第二条再执行完整后端回归，其中数据库集成测试需要 Docker 提供一次性 MySQL。不要使用日常账号或付费模型请求来代替这些并发与故障测试。
