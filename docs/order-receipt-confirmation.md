# 买家确认收货

买家在已发货订单点击「确认收货」，核对弹窗后再次确认，后台才会记录操作。首次确认把订单从 `SHIPPED` 更新为 `COMPLETED`，收货时间由数据库UTC时钟产生。浏览器和模型均不能指定或回填时间。

## 接口与权限

`POST /api/v1/shops/{shopId}/orders/{orderNo}/receipt-confirmation` 不需要请求体，要求已认证买家同时具备 `ORDER_READ` 与 `ORDER_CONFIRM_RECEIPT` 权限，并保留CSRF保护。

响应包含公开订单 `order`、幂等标记 `alreadyConfirmed` 和后台计算的售后资格 `eligibility`。订单响应新增可空的 `receivedAt`；售后截止时间取自 `eligibility.deadlineAt`，页面不根据浏览器时钟计算。

买家身份始终来自认证结果。其他买家、其他店铺或不存在的订单统一返回404；没有操作权限返回403。查询权限不会隐式授予确认收货权限。

## 事务及历史数据

- 在事务内按订单、买家和商铺锁定当前行，串行处理并发确认及取消。
- 只有 `SHIPPED` 且收货时间为空的订单可以首次确认。
- 已完成且有可信收货时间的订单返回原时间，不改时间、不增加第二条收货操作记录。
- 历史已完成但时间缺失，或状态/时间异常的订单返回业务冲突，交由人工核实。
- 更新与操作记录在同一事务内完成；操作记录写入失败时整笔回滚。
- 收货操作记录以订单ID唯一，保留操作账号、买家、商铺及收货时间。
- 已有售后申请保留其提交时的资格快照；确认收货不会重写申请历史或触发退款。

## 数据库与本地启用

V7新增 `support_order_receipt_audit`，不修改旧迁移，也不替历史订单补日期。运行账号只新增 `support_order` 的 `status`、`received_at` 列更新权限，以及收货操作记录的INSERT权限。金额、买家身份及订单删除仍不授权。

数据库管理员在V7迁移后执行 `config/order-receipt-runtime-grants.sql`。普通应用及迁移账号不代替管理员授权。已有买家账号增加独立的 `ORDER_CONFIRM_RECEIPT` 权限；本地完整账号快照需保留原账号及密码配置。

浏览器联调用一次性测试MySQL，专用订单 `SFRECEIPT01` 用于验证确认操作。日常业务库不为了测试而修改既有订单。

本地完整账号快照可使用 `tools/LocalAfterSaleSetup.java configure-receipt-buyer` 增加 `customer-200` 的收货权限。工具要求通过 `SUPPORTFLOW_APPLY_PATCH` 指定本机补丁工具，保留原账号、身份及密码哈希，私密快照仍位于Git忽略目录；它不会授予数据库权限。
