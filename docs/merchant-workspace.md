# 用户端、商家管理端与店铺授权

## 两个入口，同一工程

- 用户端：`http://127.0.0.1:5173/?shopId=100`，用于本人订单、咨询、会话、退款申请和确认收货，不再展示人工审核入口。
- 商家管理端：`http://127.0.0.1:5173/merchant`，用于获授权店铺的待审申请、审批历史、模拟执行进度和人工重试。

两个页面共用一个Vue工程、一个Spring Boot后端；独立入口不是微服务拆分。`/merchant/`同样可用。静态部署时须将这两个管理端路径回退到构建的 `index.html`，API仍反向代理给后端；不能只配置根路径首页。

本轮没有提供商家入驻、商品/库存、创建店铺、员工授权管理页面、平台超级管理员或真实支付。登录仍沿用本地Basic+CSRF，只用于学习环境，不代表已具备公网生产认证体系。

## 身份和权限不是同一回事

账号类型是服务端配置的枚举 `BUYER` / `MERCHANT_STAFF`，省略时默认买家。单独拥有 `AFTER_SALE_REVIEW` 不会升级为商家员工；前端也不能凭用户名猜测身份。GET `/api/v1/security/me` 返回账号名、类型和公开功能开关 `capabilities`，不返回密码、买家ID或凭据。V10起知识维护使用独立 `KNOWLEDGE_MANAGE`，知识专职员工不需要退款审批权限；见[知识管理说明](shop-knowledge-management.md)。

员工进入管理端需要：明确的员工账号类型、`ORDER_READ`与`AFTER_SALE_REVIEW`、有效商家与员工绑定，以及相同商家下的有效店铺和显式授权。买家账号不能调用商家接口；员工账号不能调用买家订单/聊天/历史接口。服务内部读取订单进行审批校验仍受原业务逻辑控制。

员工的数据库ID与其服务端关联买家身份分别保存，关联买家身份继续用于禁止审核/重试本人的申请。审批和人工重试在原审计中同时记录员工ID与账号；买家、系统和历史审计的员工ID保持NULL。

## 数据和请求边界

V9新增商家、店铺、员工、员工店铺授权四表，并增加审计员工字段与店铺售后索引；迁移不推断历史店铺归属，不自动创建商家或授权。

每次请求都查数据库里的当前有效状态，不缓存授权。审批/人工重试在业务事务内共享锁定授权关系：若撤销先提交，后续操作拒绝；若审批先取得授权锁，撤销等待该次事务完成。已合法批准的持久化模拟执行任务不会因后续撤销自动取消。

列表SQL先限制当前店铺再取最多50条，不能先取全平台结果再在Java或前端过滤。无店铺权限返回403；在获授权店铺中猜测其他店铺的售后UUID返回404。旧 `/api/v1/reviews/**` 统一拒绝，不保留全平台审核后门。

| 接口 | 作用 |
| --- | --- |
| GET `/api/v1/merchant/shops` | 当前员工的有效授权店铺；有效员工没有授权时返回空数组 |
| GET `/api/v1/merchant/shops/{shopId}/after-sales` | 当前店铺的待审列表 |
| GET `/api/v1/merchant/shops/{shopId}/after-sales/history` | 当前店铺的售后与执行历史 |
| POST `/api/v1/merchant/shops/{shopId}/after-sales/{id}/decision` | 审核，仍要求CSRF、意见、禁止自审及并发校验 |
| POST `/api/v1/merchant/shops/{shopId}/after-sales/{id}/execution/retry` | 对允许重试的失败任务提前重试，保留累计次数 |

## 本地配置与最小权限

账号类型参考 [`config/reviewer-account.example.yml`](../config/reviewer-account.example.yml)，在被Git忽略的已有账号记录中补充 `account-type: MERCHANT_STAFF`，不要替换密码哈希或覆盖买家账号。修改本地账号配置后重启后端；数据库店铺授权的撤销不需要重启。

运行账号只需读取四张授权表；不允许通过应用新增/修改授权。已有库级SELECT时无需再增加数据库权限。新环境按DBA流程参考 [`config/merchant-runtime-grants.sql`](../config/merchant-runtime-grants.sql)，不授予授权表写入、DELETE或DDL权限。

本地学习环境经操作者明确同意后，可运行 `tools/LocalMerchantSetup.java bootstrap-shop-100`：只登记已有 `support-reviewer` 与店铺100的本地演示关系。工具保留原账号、密码与订单，不给店铺101授权；发现已有商家归属、员工绑定或其他启用授权冲突时停止，不静默重分配。它使用已有迁移/运维账号的DML权限，不能通过运行账号自行提权。`inspect`只读输出范围元数据，不输出凭据。

## 前端操作保护

管理端店铺下拉框只来自后台授权列表；没有授权不会自动选择默认店铺。切店/退出会取消旧读取并清空旧列表，迟到响应不能污染新店铺。审批/重试未决时禁止切店和退出，并提示离页风险。结果不确定时必须先读取当前店铺记录核实，不能自动重放POST。
